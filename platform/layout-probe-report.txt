做法：在**真页面**上改 DOM 或拦截那一次 fetch，再跑一遍探针。每条之前都 reload 一次拿干净页面

变异的对象 / 手段                                        实际报出的码与文本
① 删掉 <main>                                            LP-EMPTY :: 页面里没有 <main> —— 提取失败时后面每个探测器都在空转，拒绝给结论

③ svg 设 display:none                                    LP-ZERO :: 2 个应当可见的元素几何为 0：svg 0×0 | polyline 0×0
④ 指标格 overflow:hidden + display:block + width:20px    LP-CLIP :: 1 个元素把内容截掉了：td.value clientWidth=20 scrollWidth=55 文本="-3.2043%"
⑤ section.curve 设 margin-bottom:-200px                  LP-OVERLAP :: 1 处兄弟重叠：main 下 section.curve ∩ div.groups 相交 1000×200px
⑥ polyline 的 points 改成 "0,0"                          LP-ZERO :: polyline 0×0
                                                         LP-CURVE-POINTS :: 折线上 1 个点，报告里 60 个点
⑦ 一个 th 的文本改成 "XX"                                LP-LABEL :: 1 个指标标签不是原样呈现：0：页面印 "XX"，服务端下发 "累计收益"
⑧ 删掉一个 td                                            LP-TEXT-COUNT :: 页面印了 13 格，服务端下发 14 条
⑨ 一个 td 的文本改成 "999"                               LP-TEXT :: 1 格不是原样呈现：0：页面印 "999"，服务端下发 "-3.2043%"
⑩ 详情接口被拦成 text/html（不是 JSON）                   LP-API :: 取服务端下发的那份报告失败（report-seed7-a）：SyntaxError: Unexpected token '<'
⑪ 详情 payload 里 counts.equityCurve 改成 61             LP-CURVE-COUNT :: curve.length=60，counts.equityCurve=61
⑫ 什么都不改（对照）                                      无（[]）

⚠️ 一条**没打到靶子**的变异，记在这里当方法学注记（这正是「变异没打到分支」与「探测器没写」
   在报告里长得一模一样的那种坑）：
   第一版写的是 `document.querySelector('main').style.width = '3000px'` —— **什么都没报**。
   原因不是探测器坏了，而是 main 有 max-width（760px），内联 width 被它封顶 ⇒ 那条变异**根本没造出溢出**。
   换成 ②「往 main 里塞一个宽 div」才打到。⇒ 结论：**变异要打在判据真正读取的那一侧**，
   报不出来时先怀疑变异，不要先怀疑判据（也不要顺手把判据放宽）。

C. 它量得到什么、量不到什么（边界，别读多）

量得到（就是上面 12 条）：横向越界 / 整页横向滚动 / 兄弟重叠 / 文本截断 / 该可见的东西塌成 0×0 /
  页面印的串与服务端下发的串逐字一致 / 行头标签一致 / 折线点数与报告曲线点数一致。
量不到：
  ① **好不好看**。没有设计稿可比（本仓库没有高保真稿），所以「像不像设计」「字号/色值/间距对不对」
     一条都没判 —— 那需要一份设计稿，属于另一个话题。
  ② 纵向排布是否合理（垂直方向只做「兄弟重叠」这一件事；元素之间空太多、顺序怪，它不报）。
  ③ 键盘可达性 / 焦点顺序 / 对比度 / 无障碍。这些 `getBoundingClientRect` 看不见。
  ④ **只在这一档宽度下成立**。三档是手挑的（375 / 800 / 1280），不是穷举；换一档可能不同。
  ⑤ 服务端**算得对不对**。它只对拍「页面印的 == 服务端下发的」，两侧同时错它看不出（那是
     platform-text-parity 与 I4 看板的活）。
