## 一、为什么不用缺口清单 §六 的 Sprint 0~3

那份顺序是**按层切的**：Sprint 0 补契约、Sprint 1 回测层、Sprint 2 数据层、Sprint 3 风控层。
它对每一层的定义都是「等上一层全部完成」。后果：

- 迭代结束时交不出**能跑的东西** —— Sprint 0 末只交出文档，Sprint 1 末才第一次出现代码；
- 没有**端到端**的验收物，集成风险全部堆到最后；
- 「按模块」而不是「按可演示的价值」计分。

敏捷要的是每个迭代结束都有一条**端到端能跑、能演示**的窄路径。所以本计划**重切**而不重写：
契约、DDL、门禁这三件已经做出来的东西**原样复用**，只是把「什么时候用」重新排。

变异前自断言「确实改了字节」。这两次往返当场报出了三件事：
① 第一次选的变异（改探针名单里的一个字符串）**根本不会让任何断言失败** —— 工具拒收了这个绿；
② 还原字节一致后 pytest 仍然红，真因是 `__pycache__` 的陈旧 `.pyc`（同秒写回 + 文件字节数相同，
   `(mtime, size)` 双双命中缓存）；③ 上一次运行遗留的 `.pyc` 会把**下一次**的第 1 步也毒化。
现在工具在启动时与每次往返前后都清缓存。

**收工必须交出的四个数字（全部来自真实运行，不许估算）**：门禁通过数 / 棘轮 `total` / `pytest` 通过数 / 触发测试与证伪计数。

### 11.2 一次批次的形状（五步，次序本身就是判据）

1. **前置**（不碰网、不碰库）：标的非空且可归一化、起止有序、`data_version` 非空；
   前置失败**不留批次行** —— 那不是一次批次，是一次调用写错了。
2. 在 `dc_ingest_run` 里**先写一行 `RUNNING`** —— **失败的批次才是日志最该留下的东西**。
3. `adapter.fetch_*` → `adapter.validate(frame)`；`is_valid=False` ⇒ **一行都不写**，抛

4. 帧 → 行对象：逐行盖 `source = adapter.source_name()` 与本次的 `data_version`，再交给相应的 ingestor。
5. 收尾：`status` 看**帧有没有覆盖全部请求标的**（缺 ⇒ `PARTIAL`，不是「部分行写失败」）；
   `row_count` 取 `IngestReport.total`（`inserted + skipped`）；它与「送出去的帧行数」不等

### 12.2 为什么这不是「把一个 `0.0` 改成真值」

这一条同时踩中三件**不同**的事，任何一件单独做都会留下静默的错误口径：

1. **分红是稀疏事件流，不是连续序列**（对照 B21 的复权因子）⇒ 「这一天没有分红事件」是**正常状态**，
   返回 `0.0` 与「有分红但派 0」在数值上等价；而因子的「缺一行」是**异常**，必须抛 `DATA_001`
   （B22.3 的那张表就是钉这个分野的）。⚠️ 抄错边界的人会给分红补一条「没接源必须抛」的判据。
2. **两个日期不是同一件事**（本契约里第一张「公告日 ≠ 事件日」的表，D4）：
   过滤键 / 主键 / 窗口用 **`ex_date`**（事件日），**可见性依据**用 **`announce_date`**（公告日）。
   把可见性依据写成 `ex_date` ⇒ 一条**已经公开**的方案会被拖到价格变动之后才「可见」。
3. **「读得出来」不等于「算进去了」**：`quanauto/engine.py` **一字节没动** —— 回测的
   `total_return` 里**没有分红项**，产品代码里**没有任何人调用** `DataFeed.get_dividend()`
   （B22.2 写明）。这两句的区别不是修辞：前者有 5 条 PIT 用例 + 14 条落库侧用例 + 4 份冒烟快照撑着，
   后者**一条证据都没有**。

### 12.4 本节自己不作数的地方

- **不等于 I2 收口**：关的是收口条件 **①** 的最后一个子项；**② 未动**（未确认清单 B14 / B16 /
  B17 / B21.6），真源覆盖面那件事一个字没变。
- **引擎仍然不算分红**：`quanauto/engine.py` 没动 ⇒ 绩效数字里**没有**分红项（B22.2）。
- **真库未验**：落库侧用例一律用**假连接**（断言的只是「发出去的 SQL 文本与绑定参数」）；
  「库约束已验证」这句话**仍不成立**（同 D5）。
- **真源未跑**：tushare 的 `dividend` 接口**没有凭证、从未在真实券源上跑过** ⇒ 适配器只保证
  **形状**（列名 / 类型 / 异常分类），取回的**数值**没有真样本（B22.6）。
- **多源交叉核对没做**：只有 tushare 一个源；「两个源对同一条分红给不同每股派息」时该信谁，**没定**。
- **送转 / 配股 / 转增 / 分红税 / 股息率基准都不建模**（B22.6 逐条登记）。
- **没有产品入口**：`quanauto/cli.py` **不开**采集子命令（与 §11 同一条理由）。
