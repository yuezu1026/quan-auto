    状态矩阵演示

    通用 每屏 × 五态：默认 / 空 / 加载 / 错误 / 锁定

    1怎么用

    左侧「状态演示」把五态套在当前屏上。换一屏状态会重置为默认 —— 状态属于屏，不是全局开关。

    状态 这一屏要回答的问题 低保真画到哪
    默认 正常时看到什么 完整结构
    空 为什么空？下一步做什么？ 一句原因 + 一个动作入口；空白页不是答案
    加载中 慢的时候能不能不闪、不跳、不假装有数 骨架块 + aria-busy，不显示旧数字
    错误 谁错了、能不能重试、旧数据还显不显示 错误码 + 重试；不把旧数据留在屏幕上
    锁定 为什么不能操作、要谁来解锁 只读横幅 + 动作按钮 disabled，不隐藏按钮

    2这一屏自己不主张什么

    • 它不主张任何一屏已经实现了这些状态 —— 它只是一份 「得有这么几种状态」的检查表。
    • 「锁定」这一态在真实产品里跟环境 / 权限有关；低保真不画权限矩阵。
    • 加载与错误的具体文案属于实现，这里画的是位置与优先级。

    这份原型的自我约束（与 index.html 同一套）

    • 没有牙：它是设计产物，不是规格、不是契约、不是门禁。说得再对也不构成证据。 仓库里的判据只有 tools/run_all_gates.py 跑的那组门禁与 pytest。
    • 不主张「页面受控」：本仓库的布局 / 视觉 那一格仍然零覆盖。加上交互也不会让那一格变成有判据的 —— 可点不等于被验证。
    • 不放真数据、不发请求：全部数字是页内常量里的示意值， 连「采集进度」都是本地定时器；页面不访问网络， 也没有 CDN / 外链字体 / 图片 / 构建步骤，file:// 直接打开即可用。
    • 不用颜色（只有灰阶 + 反白）、不写视觉规格 （不写品牌色 / 动效时长 / 精确圆角）。低保真的目的是让人讨论结构， 引入观感会让人开始讨论观感。
    • 交互细节只画到「有这一条」：键盘焦点可见有、aria-* 标签有、空/加载/错误/锁定四态有；具体的动效曲线、快捷键表、 无障碍规范的落地属于实现。

    关掉 JS 会怎样

    八屏 + 状态矩阵会纵向堆开，退化成一块静态线框板（也就是 index.html 的用法）；导航与状态控件会被隐藏， 因为它们在没有 JS 时不会有反应，留着只会骗人。 降级不是「功能少一点」，而是「不假装还能点」。

    页内自检检的是什么

    左上角那支「跑一次页内自检」逐项检查本页自己的口径 —— 8 屏 + 状态矩阵都在、14 条指标的分组是 3/4/6/1、风控 6 条规则不重名、 只拦开仓的是 5 条、显示串里只有 percent 带 %、 示例串的小数位与规格表一致、试算的四个样本（干净 / 超限 / 熔断 / 卖出不熔断）落在预期裁决上、 阈值校验对四种坏值与一种好值给出预期结论、生命周期守卫拦得住越级。 另有一组盯的是交互底座本身： <body> 上不挂 data-proto-* 钩子属性（挂上去会让钩子选择器先命中 body，后面的分支静默变死代码）、 全局状态住在 data-ui-* 且与内存里的 state 一致、 Kill Switch 的 aria-pressed 必须落在按钮上、 确认框「关闭 / 取消 / 确认」三条出口都得关得掉（且取消不动 kill）、 状态单选组与当前状态一一对应、F2 的 schema 下拉真的能筛（选项数对齐 + 筛后与数据一致）、F1 十盏灯都指向真实存在的屏、 F3 黑名单的三条分支（空标的拒 / 新标的收 / 重复标的拒）与两张表同步。 一个探测器一个样本，且带一个期望 0 报错的干净控制组。 它检的不是仓库实现 —— 那不是这个文件能主张的事。
