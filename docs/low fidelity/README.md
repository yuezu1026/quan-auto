# 低保真 UI 线框（Low-Fidelity Wireframes）

把 `docs/智能量化交易平台.md`（PRD）里的模块与流程画成**低保真线框**，用来讨论
「有哪些屏、每屏放什么、谁拥有那个权限、出错时什么样」。

**这是一份设计产物，不是界面规格，也不是实现计划。**

## 怎么看

直接双击 `index.html` 用浏览器打开。**零依赖**：没有 CDN、没有构建步骤、没有网络请求、
没有外链字体与图标；所有留白与字号都是固定的低保真取值。

## 这是什么

- **线框**：只表达**结构与信息层级** —— 有哪些区域、每个区域放哪一类信息、什么在主什么在次、
  交互入口在哪里、空/加载/错误时显示什么。
- **流程与状态**：两条主循环的界面路径（日频交易循环巡检、策略进化循环的提案审批），
  以及每屏的几种状态。
- **需求追溯**：每一帧都点名它服务的 PRD 模块与「落地路线图」的阶段（MVP / 完善版 / 进化版），
  `index.html` 末尾有一张完整的追溯表。

## 这**不是**什么（重要）

- **不是规格、不是契约、不是门禁**。它没有牙 —— 就算它写得再对，也不构成任何证据。
  仓库里的判据只有 `tools/run_all_gates.py` 跑的那一组门禁与 pytest。
- **不主张「页面受控」**。本仓库的**布局 / 视觉**那一格**仍然零覆盖**：线框只是一张纸，
  它不解除任何缺口，也不把那一格变成有判据的。
  （那一格的现状与豁免记录见 `docs/智能量化交易平台.md` 附录C §C.14。）
- **不主张未开工的模块有任何实现**。除 F5 之外，本文件里的每一帧都是**提案**，
  在图上用**点划线框**标出，含义是「结构占位」而不是「已经能做」。
- **不写像素规格**。低保真刻意不写颜色值、字号、圆角、间距的具体数值 ——
  那些属于视觉设计，写在这里会假装自己是规格。
- **图里的每个数字都是示意值**：不是报告读数、不是阈值真值、不是数据规模。
  示例行写占位符（如 `<策略ID>`、`<数据版本>`），避免示意值被当成事实。
  **「有几条」「有几格」「有几个阶段」也不代表仓库真值** —— 线框要表达的是「界面上得有这么一块」，
  具体条数以仓库里的契约 / DDL / 实现为准（第 6 节末尾把几处刻意合并、刻意省略的地方单列了一段）。

## 内容清单

1. **信息架构**：五个一级区（总览 / 数据 / 研究 / 交易 / 绩效）+ 常驻顶栏
   （环境徽标 + 全局 Kill Switch）。
2. **两条主流程**：日频交易循环、策略进化循环。
3. **八帧线框**：F1 平台总览 · F2 数据中心 · F3 股票池管理 · F4 回测实验室 ·
   F5 绩效看板 · F6 风控控制台 · F7 策略中心与生命周期 · F8 组合调度与研究 Agent。
4. **状态矩阵**：每屏 × 五种状态（默认 / 空 / 加载 / 错误 / 锁定）。
5. **追溯表**：帧 ↔ PRD 模块 ↔ 路线图阶段 ↔ 交付状态；表后面跟着一份
   「没有画进来的几件事」清单 —— 缺失是刻意的，不是遗漏。

## 与已交付那一屏的关系

只有 **F5 绩效看板**在代码里有对应物：`platform/web/src/App.jsx`（React 单页，读只读 REST）。
线框与它对齐在三件事上：

1. **每个绩效数字都是服务端算好下发的文本**，页面上原样呈现；前端不换算量纲、不决定小数位、
   不重算任何指标（「两侧各算一套」就是 bug）。
2. 指标由**服务端规格表**驱动（键 / 分组 / 标签 / 量纲 / 小数位 / 行序），页面**不手抄**规格表；
   分组顺序从服务端数据里推导。
3. 报表抬头把**可重现性**需要的字段摆出来（报告 id、标的、窗口、策略与版本、数据版本、结构计数）。

这三条都已经有门禁盯着（`platform-spec-parity` 管声明层、`platform-runtime` 管运行层、
`platform-text-parity` 管两侧显示规则、`platform-web-parity` 管这一页读了哪些字段与谁在格式化数字）。
线框落地成代码时要接的就是它们。**其余七帧没有对应代码。**

## 已知的内部张力（刻意保留，不是笔误）

这几处看起来像自相矛盾，其实是**同一件事的两种粒度**，或者**照抄出来的产品侧缺口**。
写在这里，是因为它们是「有人来问为什么不一致」时最可能被问到的四个点。

1. **F4 要四项可复现凭据，F5 抬头只画了两项。** F4 的备注要求「数据版本 / 策略版本 / 参数 / 随机种子」
   四项齐备（少一项，报告就从证据退化成一张好看的图），而 F5 的抬头只画到前两项。
   **F5 是照抄已交付页面的**：它长什么样就画什么样，所以这个差不是画错，而是把产品侧的待补项
   如实暴露了出来。**要修就修产品侧，不要修这张线框** —— 改了抬头，四条平台层门禁的比对对象就断了。
2. **同一件东西在不同地方数出不同的「步数」。** 交易链在「两条主流程」与总览的节点灯里都是十步，
   而总览的「今日巡检清单」只有六行（它是当日任务书，合并了几步）；
   策略进化循环在「两条主流程」里是九步（含落地阶段），在 F8 的 Agent 提案流里是八步。
   **数的范围不同**，不是两份互相独立的状态表 —— 别拿格数去对步数。
3. **规则条数不要拿 F6 去对账。** 需求里「单票买入上限」与「单票集中度」是两条，
   落到实现是同一条口径（该标的持仓市值 / 账户总资产）⇒ F6 合并成一行；
   名单型的黑名单也被移出了数值表（它的操作形态是增删条目，不是一个阈值）。
   **以仓库里的风控契约与 DDL 为准。**
4. **环境徽标有三种取值，本稿只用到两种半。** 研究（F2 / F3 / F4 / F5 / F7 / F8）、生产（F6），
   以及 F1 的跨环境总览（它读的既有研究侧也有生产侧的事实）。**「模拟」没有对应屏** ——
   它只出现在 F7 的生命周期阶段里，缺失项登记在第 6 节末尾。

## 这份线框的自我约束

- **不用颜色**：只有灰阶 + 反白。低保真的目的是让人讨论结构，引入颜色会让人开始讨论观感。
- **不填真数据**：所有表格里的行都是示意行。
- **不画交互细节**：悬停、动效、键盘焦点顺序只写「有这个要求」，不画状态图。
- **不替代无障碍规范**：线框只标注「这里需要 label / 这里需要焦点可见」，具体落地属于实现。

## 每个 frame 与 region 都带 `data-wf-*` 属性

`data-wf-frame="F1"`、`data-wf-region="..."` 是为了让以后**有人想写静态探针**时能数得出来
「有几帧、每帧几个区域、有没有漏注释」。**现在没有这样的探针**，属性只是留个抓手。

若要写这个探针，有一条环境约束先记住：`index.html` 与这份 README 里含少量 GBK 之外的字符
（对勾 / 叉 / 三角 / 双箭头一类）。本机控制台是 cp936 时，**直接把它们 `print` 出来会抛
`UnicodeEncodeError`** —— 探针要么以 `-X utf8` 跑，要么把输出重定向到文件再读，
**不要靠终端回显判断结果**。
