1 怎么看这份线框

低保真的目的是让人讨论结构，不是让人讨论观感。所以这份稿子刻意做了三件事， 读的时候请按这个前提来：

  • 不用颜色：只有灰阶 + 反白。危险动作用反白表示，不用红。
  • 不填真数据：表里的行都是示意行，写 [策略ID] 这类占位符。
  • 不写像素规格：不写字号、圆角、间距的具体数值 —— 那些属于视觉设计，写在这里会假装自己是规格。

每帧的头部右侧写着它的需求追溯（PRD 模块号 + 落地路线图阶段 + 交付状态）， 完整对照见 6 追溯表。

系统有两条循环（PRD §一 的「双循环」）。两条循环在界面上的差别很大，所以分开画。

界面含义：这条链上的每一步都要在总览上有一个可点进去的节点灯， 并且「卡在哪一步」要一眼能看到。风控校验是唯一一个可以否决整条链的节点。 十步就是十盏灯：总览上的节点灯与这一行一一对应（含末步「反馈回池」）； 而总览里的「今日巡检清单」是另一种粒度 —— 它是当日任务书（几点跑的、产出什么）， 合并了几步，所以格数少于灯数。两处不是两份互相独立的状态表。

界面含义：这条链上的每一步都产出一份可审计的中间物（诊断报告、diff、回测结论、压力测试结论）， 界面的任务是让人能在两三分钟内判断「要不要点那个晋级的按钮」。 每一步都能停，停下来的状态必须是「待人工」而不是「失败」。 分段说明：前七步（失效检测 → 压力测试）是 Agent 流水线，在 F8 里逐步画； 第八步「人工晋级决策」之后是落地阶段（模拟盘 / 灰度 → 正式服役）， 它属于 F7 的生命周期状态机，不是 Agent 的步骤。所以同一件事在这里数出九步、 在 F8 的提案流里数出八步 —— 那是数的范围不同（这里含落地阶段，F8 只算到「晋级推荐」）。

两条循环的界面边界：交易循环追求「不需要人」；进化循环追求「每一步都要能给人看」。 所以前者用状态灯与存量计数，后者用可展开的证据链。

类型 对象 提案摘要 证据 动作

这是「待人工」这一类动作的汇总入口，不是全部动作的清单： 只收已经生成提案的几类。参数变更（F7）与 Agent 代码评审（F8）在各自屏上就地处理， 不重复搬到这里；本屏的动作按钮只做批准 / 驳回，落地一律跳对应屏。

  1. 顶栏的环境徽标常驻、不可关闭。研究环境看的是历史数据，看到的结论与生产环境不是同一个东西； 界面必须让人随时知道「我现在站在哪一边」。本屏是这条规则的例外：它读的东西一半在 研究侧（双循环节点灯、待人工决策），一半是生产侧的事实（当日巡检的真实批次时间、 指令与判定计数、Kill Switch 状态、阈值变更审批），所以徽标写的是「跨环境总览」 而不是某一个环境 —— 贴一个环境标签撑不起这屏的内容。
  2. Kill Switch 在每一屏的顶栏都可达。「风控拥有最高权限」这件事，在界面上首先体现为 入口不藏：不允许把它收进二级菜单。
  3. 巡检清单的每一项都能点进去，分别落到 F2~F8。本屏不另做一份状态页： 状态只在这两处出现 —— 节点灯（全链十步，回答「走到哪」）与巡检清单 （当日任务书，回答「几点跑的、产出什么」）。两者粒度不同、格数不同，是刻意的； 但它们不是两份互相独立的状态源，别指望拿一个去校验另一个。
  4. 「待人工决策」是本屏唯一写操作区。Agent 只能提案不能落地：晋级按钮是人的动作， 且必须走 F7 的状态机，不能在总览上直接改状态。
  5. 状态用文字 + 形状，不用颜色（低保真不引入颜色语义；落地时也要保证灰度可读）。

已知缺口（刻意照抄现实，不是笔误）：K 线要行情序列（OHLCV），而报告里没有它。 报告里只有净值曲线（逐日 equity_curve）、成交流水（trades）、委托流水（orders）三类。所以 K 线现在只能是占位块；要修就修产品侧 —— 让契约把「行情序列」加出来（回测输出带上 OHLCV），不要让页面自己去找行情文件另算一份。
  1. 报告必须记全「数据版本 / 策略版本 / 参数 / 随机种子」，四项缺一不可复现。 所以它们在跑之前就显示出来，而不是跑完才藏进 JSON。
  2. 区间校验失败时不许提交。提交后报错会让人以为「跑过了只是没结果」。
  3. 复权口径里没有「前复权」这一项。界面不给选项，比在说明里写「请不要用前复权」有效。
  4. 回测库必须含已退市股票。只拿「今天还在交易」的票去跑历史，会系统性地高估收益 —— 这是数据侧的要求，但界面要把它写在配置里，否则没人看得出那个池子干净不干净。
  5. 这一屏产出的报告就是 F5 读的那一份。两个页面必须读同一份文件， 而不是各自有一份「给页面用的副本」。
  6. 三态：空（没选策略）/ 加载（进度条 + 可取消）/ 错误（校验失败，含可点的后续动作）。
  7. 两个图都要有「数据来源」才画。买卖点来自成交流水（一笔成交一个点， 所以现在就能画）；K 线要行情序列（OHLCV），回测报告里没有它 —— 这是契约缺口，不是这一屏的问题。

没有画进来的几件事（记住它们的缺失是刻意的）

  • 收益归因的三张表（资产配置 / 风格 / 策略贡献）：它们应该是 F5 的一级标签页， 而不是新的一屏；本稿没画，是因为 F5 已经交付而现有页面没有这一层 —— 属于「已交付屏的待扩展项」。 （第 2 节信息架构里「收益归因」按同一个判断写法画。）
  • 执行层的其余结构：订单拆分、智能路由、持仓同步、模拟盘 / 实盘切换。 F8 只画了「成交回报 + 滑点」这一面，因为那一面是成本分析的输入；其余几面是执行引擎自己的事。
  • 组合调度的再平衡触发：本稿只画了手动覆盖，没有画「定期 / 阈值 / 事件」这三类自动触发 在界面上怎么呈现、怎么看得见。少了它，「多久动一次仓」这个问题在界面上没有落点。
  • 以「模拟环境」为主语的那一屏：环境徽标有三种取值，本稿用到研究（多数帧）、 生产（F6）与跨环境总览（F1）；模拟盘只出现在 F7 的生命周期阶段里，没有单独一屏。
  • 多用户 / 权限 / 计费：PRD 明确第一版完全自用、不做这些。所以本稿里没有登录页、没有角色管理。
  • 视觉与品牌：低保真刻意不涉及，见下一节。

7 这份线框不主张什么

逐条写明，避免被当成证据引用：
  • 它不是界面规格、不是契约、不是门禁，也不构成任何判据。
  • 它不解除「布局 / 视觉仍然零覆盖」这一条 —— 画了线框等于有了一张纸， 不等于有人守着布局。那一格的现状见 docs/智能量化交易平台.md 附录C §C.14。
  • 它不主张除 F5 之外的任何一帧已经有实现；也不主张 F5 的实现与本稿逐像素一致 （F5 是对已交付页面结构的重新绘制，不是它的规格）。
  • 它不主张里面的字段名、表名、计数、阈值是真值 —— 全是示意值。
  • 它不是平台层开工的信号：平台层那一层有它自己的四条门禁与边界裁决， 本稿不改动其中任何一条。

低保真 UI 线框 · 依据 PRD 绘制 · 设计产物，不是规格、不是契约、不是门禁。
